## Historical limitations — initial prototype

The ESP32 app has **not been cross-compiled**: no ESP-IDF or Xtensa tools were found. No device was flashed or purchased. ESP-IDF 5.3.1 is a compatibility candidate supported by the vendor instructions, not a verified build lock. Gameplay has no external runtime npm packages; the optional Garage connector reuses the existing Monstopia S3 SDK installation on this Mac. Node 24.13.0 was used for tests. [Node's native TypeScript documentation](https://nodejs.org/api/typescript.html) explains its type-stripping limitations.

Firmware currently supports the serial game loop and NVS source only. Physical display/touch, motion detection, NFC, GPS, asset download/SD activation, BLE, event outbox and Wi-Fi sync require the next bring-up milestone. The browser uses its local service; closing that service pauses browser play. The shared firmware game core has no network requirement.

Development pairing does not authenticate physical ownership. Saves replay legally but do not prove genuine walking/NFC use. The service refuses production mode. After an abnormal process exit, its writer lock requires explicit inspection/removal only after confirming no writer is alive (see API guide). Save recovery and firmware migration still need real power interruption testing. Battery compatibility and deep-sleep step tracking remain open hardware decisions.

## Reproduce optional browser verification

The normal `npm test` needs no npm dependencies. Optional importer tests require a Python environment with Pillow; optional browser tests reuse Playwright. Browser verification can reuse an existing Playwright installation and browser, or a separately approved installation:

```sh
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs \
PLAYWRIGHT_CHROMIUM=/path/to/chrome-headless-shell \
npm run test:browser

# With the same environment variables:
npm run test:browser:assets
```

The run used existing Playwright 1.62.1 and cached Chromium build 1243. It creates a fresh temporary test profile/save store, closes both, and stores only nonsecret results/screenshots in `docs/evidence/`.
